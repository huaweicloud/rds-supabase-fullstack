# rds-supabase 技能族改进方案（已评审 · 记录待办，未实施）

- 日期：2026-11-11
- 状态：**方向已确认，暂不实施**——按批次择期落地
- 适用范围：`skills/huaweicloud-supabase/` 全技能族（web-build 编排 + 六个专项技能）
- 验证纪律：每批照旧——validate_skills + skill-lint + 测试 + CHANGELOG + 双分支推送

## 背景与目标

用户目标：AI Agent **平稳、可靠、稳定**执行；**省 token**；流程**不偏离、严遵循、不走偏**；**准确执行、正确处理**；**不断联**；**平滑推进**。

一句话结论：现在这套技能是"**靠 agent 自觉 + 出事后抽查**"，要改成"**不自觉就过不去 + 只读该读的**"。三招：

1. 把"要求"变成"检查"（gate/trace 加检查项）
2. 把"大文档"变成"按需小卡片"（瘦身、拆分、单一出处）
3. 把"散文"变成"表格"（错误处置表、等待规则）

## 8 个翻车场景与对策

| # | 场景 | 现状为什么拦不住 | 对策 |
|---|---|---|---|
| 1 | **忘了问用户**：步骤三写"禁止跳过"，但 agent 上下文一长就忘，直接开始建实例 | "用户确认过"无记录，事后查不出 | 用户每次勾选/确认，**强制记一行 trace**（如"用户确认：实例=用已有的"）；步骤收尾 gate 查这行，没有即 FAIL |
| 2 | **抢跑/越级**：步骤三没做完就跑步骤五的 SQL | 白名单是事后审计，事中无拦截 | gate 加**进门检查** `check-entry`：进步骤前校验 webapp.json 上一断点在位，未过即拒绝 |
| 3 | **抄错 ID**：长会话把 app-123 抄成 app-132，对错实例执行写操作 | 无任何拦截 | **写操作前必须回 webapp.json 重读 ID**（不信对话记忆，只信文件），trace 记录回读值 |
| 4 | **说读了没读**：步骤五"已读 best-practices"自报即过 | 无读取证明 | trace 记 `read:best-practices` / `read:usage`，check-gate 3/4 前置校验 |
| 5 | **token 白烧**：SKILL.md 常驻 300 行；步骤三单条目 500 字整段（含已执行过的安装细节）；九行看板每次完整重发；同段命令 4 处拷贝 | 渐进加载已有但粒度太粗，重复存储多 | SKILL.md 瘦身到 ~120 行骨架；workflow-stages **拆 9 个步骤小文件，进哪步读哪步**；每步配最小执行卡（≤50 行）；命令/约束单一出处，其余指针引用；看板保留完整重发但精简列 |
| 6 | **断连重做**：build 完成、状态未写就断线，重连从头再来 | 步骤内部无动作级检查点 | 每个大动作完成**立即记 trace + 状态增量**；重连照 trace 跳过已完成（配合既有幂等 IF EXISTS） |
| 7 | **报错后自由发挥**：错误处置是散文，没写到的错误 agent 自己编 | 无结构化错误分类 | 每步配**错误处置表**（错误类别｜判定｜处置｜上报格式）；表外错误→停下问人 |
| 8 | **命令凭记忆瞎写**：hcloud 命令名靠猜 | 仅 function-graph 有自校准 | **命令自校准推广全家**：每个 CLI 命令族首次使用前 `--help` 核实 + trace 留痕，未核实不执行 |

## 实施批次（先易后难）

| 批次 | 内容（场景） | 改动性质 | 预估版本 |
|---|---|---|---|
| 第一批 | 进门检查 + 确认留痕 + ID 回读 + 读取证明（1/2/3/4） | gate/trace 纯增量，低风险 | web-build v0.12.x |

## 各技能横向不足记录

- **web-build**：上述全部；workflow-stages 单条目巨段
- **rds-supabase-frontend**：有快照-分支机制，但**无任何 gate**——考虑轻量检查脚本（托管/发布断言）
- **rds-supabase-mgr-mcp**：散文体长文档，无结构化场景卡
- **rds-supabase-postgres-best-practices / rds-supabase-usage**：强制门读取无证明
- **rds-supabase-function-graph**：机制最完整（自校准 + 独立 gate + 21 测试）——**作为反哺源**，向全家推广其模式

## 度量目标

- SKILL 常驻上下文 ≤ 1/3（约 120 行）
- 白名单违规 = 0；关键交互确认留痕缺失 = 0
- gate FAIL 整改重跑率逐批下降
- 每步骤平均 token 消耗可对比（重构前后基线）

## 权衡与风险

- 文件拆分增加文件数与维护面 → skill-lint 结构断言护航
- 机器检查增加执行步骤 → gate 均为本地轻量脚本，成本可忽略
- 看板精简与可见性取舍 → 保留完整重发，仅裁字段
