# MCP 异常与恢复规则

## 本地执行状态

prepared → submitted → accepted 或 unknown；prepared → cancelled。
prepared 的过期由 expires_at 判断；数据库仍可显示 prepared，不等于仍可执行。cancelled 终止该计划，不产生云请求。
claim 使用原子事务，submitted 表示已取得本地执行权，不证明请求到达后端；进程此时崩溃按未决处理。accepted 只证明受理。unknown 保留人工/后续核对入口。
当前没有任务终态自动解除流程；submitted/accepted/unknown 同意图阻断重复执行。不可删除账本、换目录或换身份绕过。此机制不是跨机器或云端幂等保证。
目标需补充证据驱动的核对流程和资源级并发控制；现阶段不新增猜测终态的自动解锁。

## 异常决策表

| 事件 | MCP 行为 | 用户/运维下一步 | 禁止行为 |
|---|---|---|---|
| 未知字段/非法组合 | 提交前拒绝，不回显原始值 | 对照工具契约；必要需求不支持则暂停 | 静默丢弃、任意透传 |
| 不具备权限/写开关关闭 | 不执行写操作 | 由管理员核对身份及最小权限 | 自动换高权限账号 |
| 方案过期/参数改变 | 拒绝 claim | 重读状态、生成新方案并确认 | 复用旧确认 |
| 资源状态冲突/受保护 | 执行前阻断 | 核对状态或保护原因 | 取消保护后自动重试 |
| 用户取消 prepared 方案 | 原子标记 cancelled | 返回本地已取消 | 声称取消云任务 |
| submitted 后用户取消 | 拒绝本地取消，保留记录 | 查询任务和资源，说明任务可能继续 | 宣布回滚、删账本 |
| 写请求超时/断连/不可信响应 | 标记 unknown | 查记录、任务与资源，必要时服务侧核对 | 自动重发 |
| 服务明确拒绝 | 目标：按已确认错误分类；当前提交后异常保守 unknown | 依据请求关联信息核对是否产生副作用 | 仅凭HTTP错误推断绝无副作用 |
| 任务失败 | 记录任务证据和资源现状 | 分类人工处置或重新授权的补偿 | 把失败视作所有资源自动回滚 |
| 多步部分完成 | 报告已完成/未完成及资源来源 | 优先保留证据；清理本次资源须授权 | 删除原有PG/网络资源 |
| 任务成功但回查不一致 | 报告不一致，不报业务完成 | 有界观察或联系服务侧 | 无限轮询/改状态凑成功 |
| 凭据失效/文件无效 | 停止后续调用，保留记录 | 更新有效凭据并核对已有任务 | 重发此前未知写入 |
| SDK迁移/客户端降级 | 验证契约与账本兼容，禁写可用于止损 | 固定可用版本并完成回归 | 把程序回退当作云变更回滚 |

## 结果与重试

读查询可在后续实现中采用有界退避，但权限/参数错误不重试；当前 REST 客户端无自动重试。写请求无后端幂等契约时禁止自动重试。轮询次数/超时作为配置约束明确后实现；超时返回未决及可继续查询标识。
仅资源状态匹配不能替代任务成功，尤其 ApiKey 记录切换后仍可能有恢复步骤。业务连通验证可能需要客户/数据面参与；报告实际验证层级。

## 审计与秘密

持久账本存意图摘要、状态和任务ID，不存原始凭据/请求体。未来多步账本只存必要非敏感资源关联。审计覆盖预览、取消、拒绝、提交、观察；客户端负责确认交互证据，不声称一个布尔值可验证人类操作。秘密泄漏事件应由操作方轮换并按组织流程处置，不在聊天或错误里重复秘密。

## 0.3.3a1 异常返回增量
HTTP错误增加error.recovery.category/next_action/automatic_retry=false。400/401/403/404/409/429/5xx分别提供参数、认证、权限、目标不存在、状态冲突、限流与服务异常指引；不推断业务副作用。提交后的异常统一submission_unknown，附plan_id供核对，不自动解锁。其它原有错误可没有recovery，调用方不得因此认为可重试。未返回原始云错误体。
