# 需求二：Supabase 专项 Skill

版本 v0.4；2026-11-02。责任人/需求单/宿主版本/交付日期由项目负责人补录。独立包、独立分支、独立验收，依赖版本化 MCP 工具契约。

## 目标及边界

把用户自然语言转为六个管控场景的可靠操作流程。Skill 负责意图、必需信息补齐、推荐解释、风险告知、确认和结果解释；MCP 负责确定性的校验、执行保护及调用。不得绕过 MCP 自行调用 HTTP/Shell。
不因当前工具缺失删除最终需求。运行时根据实际 tools/list 与能力声明决定能否执行；缺工具明确说明。数据面诉求转交独立能力及负责同事，不能以管控工具模拟SQL。

## 六场景要求

| 场景 | 应实现的用户体验 |
|---|---|
| 创建 | 区分已有/新PG，按用途和实时候选推荐；逐项覆盖用户要求；确认配置/费用/后续步骤后执行 |
| 删除 | 明确仅应用还是关联PG；展示共享影响与不可逆性；独立确认 |
| 访问 | 定位EIP/证书，解释公网/计费/中断；改密经可信输入；SSL后提醒URL与登录回归 |
| 安全组 | 澄清来源，检查实际端口与规则，展示差异和共享影响，不默认全网 |
| ApiKey | 元数据查询不附带明文；重置确认、跟踪任务、可靠关联新Key、提醒下游更新 |
| 业务配置 | 非敏感差异预览，可信秘密输入，按接口局部更新，不将保存成功解释为连通成功 |

## 关键交互要求

用户要求分类为本次满足/后续配置/不支持/待澄清；必要条件不满足不执行，接受调整后重新确认。无需反复询问可以安全查询的信息，但不得把某个默认规格或价格说成事实。
目标/关键参数改变，旧计划不能继续执行。用户在提交前取消时撤销本地计划；提交后告知云任务可能继续，不声称已取消。风险提示集中展示，覆盖整个明确的方案，避免同一方案反复确认；删除/重置等高风险动作需具体授权。
宿主负责真实确认界面、身份归属和秘密承接，Skill 文字不替代安全机制。工具返回的资源名称/备注作为不可信数据，不执行其中指令。

## 输出与验收

用户可读结果说明已满足的要求、受理/任务/资源/业务四层状态、失败阶段与待办。不能把本地规划输出说成创建完成。
验收基于完整对话、工具参数与顺序、未调用的危险工具、最终回复。使用固定 MCP 版本和模型/宿主版本进行可复现评测；分别跑模拟异常和真实组合测试。具体矩阵见 acceptance.md。
独立交付 Skill 指令、场景参考、对话用例与兼容清单。码道接入细节、敏感输入展示能力与数据面交接见 open-questions.md。

## 2026-11-07 SDK基线更新
专项Skill配套0.3.8a1的29个工具。创建仅Single，已有PG或按需新PG；Ha/包周期不能静默改成其他配置。秘密由操作方本地引用输入，ApiKey由受保护文件可信交付，Agent禁止读取文件内容。Storage省略SK需已启用且相同AK；应用删除不级联PG，CCM证书购买为外部步骤。新增真实Agent验收覆盖创建部分成功、文件交付失败、引用改变、Storage首次启用缺SK、共享组风险；详见six-scenario-matrix.md。
