# Skill 编排与异常规则

先查询工具列表/能力；按当前提供的工具契约调用，不根据目标需求文档编造工具名。
标准顺序：理解要求 → 定位目标 → 查询必要状态 → 对照能力说明要求覆盖 → 展示方案 → 用户确认 → 执行一次 → 查询任务/资源 → 分层说明结果。

| 事件 | Skill 必须做 | 不得做 |
|---|---|---|
| 创建含未支持字段 | 说明是否必要、是否独立后置操作；必要条件未满足暂停 | 删除该要求后直接创建 |
| 用户调整范围 | 重做方案并确认，旧计划在可用时取消 | 继续用旧plan_id |
| 预览后取消 | 调cancel_supabase_plan；工具缺失则停止执行并说明计划仍待过期 | 宣称云端已撤销 |
| 已提交后取消 | 查询记录/任务，解释任务可能继续 | 调另一个写工具模拟取消 |
| 缺工具/未知契约 | 明确能力缺口及可完成部分 | 拼HTTP请求、借Shell执行 |
| 202受理 | 报告已受理、保留job/plan标识 | 宣布完成 |
| 超时/unknown | 查本地记录和资源，停止重放 | 换身份/目录绕过幂等 |
| 多步部分成功 | 列出已完成与剩余项，清理另行确认 | 删除用户原有资源 |
| 获取明文请求 | 仅在可信展示能力可用且获授权时执行 | 把明文注入普通对话 |
| SSL切换 | 保留中断告警，提醒针对性检查URL/OAuth/模板和登录 | 自动全量替换http/https或修改SMTP host |
| Key重置 | 分别核对任务和记录，新ID须可靠关联 | 假设最新列表记录就是新Key |
| 配置保存成功 | 报告保存结果及未做的连接验证 | 宣称SMTP/GitHub登录一定可用 |

确认方案由客户端承接，MCP只验证本地计划绑定。无法证明用户确认时不声称存在强人机绑定。
当前可用工具参数见 MCP 工具契约；数据面交接只传非敏感目标及用户诉求，不能附带管理AK/SK或ApiKey明文。

0.3.7a1：任务观察工具已提供，但completed不等于业务完成；unknown/failed/观察预算耗尽不重放写入，不自动解除账本。验收需检查超预算不无限循环、失败不换身份、order_id不冒充job_id。创建秘密通道、Storage冲突和新Key关联仍开放。
